# SideQuest Autonomous Agent Studio Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a secure, anywhere-accessible SideQuest command center whose database-backed agents coordinate internal work autonomously while every outbound, publishing, billing, purchasing, and production action remains under Thomas's control.

**Architecture:** Extend the private Supabase `ops` schema with durable workflows, leased jobs, evidence, memory, approvals, and audit events. A Vercel-hosted Vite application provides Thomas-only browser access and a narrow device-authenticated worker broker; a guarded Windows runner checks the broker before invoking Codex, so empty queues use no model allowance. The responsive frontend renders a real-data isometric studio plus operational tables and approval controls.

**Tech Stack:** PostgreSQL/Supabase migrations and pgTAP; PowerShell 7 plus Windows PowerShell 5.1 compatibility; Codex CLI with ChatGPT authentication; Node.js/TypeScript; Vite; Vitest; Playwright; `@supabase/supabase-js`; Vercel Functions; SVG and vanilla CSS.

**Spec:** `docs/superpowers/specs/2026-10-23-autonomous-agent-studio-design.md`

## Global Constraints

- Never read or write Supabase `public`; all business data and procedures stay in private schema `ops`.
- Never send email, DMs, texts, proposals, invoices, or posts; Thomas performs the external action after review.
- Stripe remains limited to customer records and draft invoices; never finalize, send, pay, void, refund, or delete.
- Vercel automation may deploy only approved previews and must never disable protection outside `mockup-*` projects.
- Never purchase, upgrade, create a paid resource, or fall back to OpenAI API-key billing.
- Keep every secret out of Git, browser JavaScript, prompts, result files, and logs.
- The runner must require ChatGPT tokens, built-in provider `openai`, official ChatGPT HTTP/WebSocket endpoints, and approval policy `on-request`.
- Empty worker heartbeats must exit before model invocation.
- No bulk migration of existing leads; start with newly eligible records and at most five explicitly tagged canary leads.
- No live Supabase migration, Vercel production deployment, schedule installation, plugin permission change, or Claude-task retirement without a separate explicit approval at that checkpoint.
- The current Claude dashboard and agent tasks remain available until their replacements satisfy the cutover criteria.
- UI copy uses sentence case, no invented business facts, no em dashes, no pulsing status dots, and no generic horizontal KPI strip.
- All times and schedule labels use `America/Chicago`.

## Review Focus

- Two workers request the same job simultaneously: Task 2 tests that exactly one lease is returned and the other request gets no work.
- A browser user is valid in Supabase Auth but is not Thomas: Task 3 tests every read and mutation route returns `403` before a database call.
- A worker submits malformed, wrong-agent, or prompt-injected output: Task 6 tests schema rejection and confirms no job, lead, approval, or handoff mutation occurs.
- Thomas double-clicks or retries an approval decision: Task 4 tests idempotency and confirms one decision event with no external action.
- The PC disappears during a job: Tasks 2, 5, and 9 test lease expiry, safe requeue, visible `Worker offline` state, and no duplicate handoff.
